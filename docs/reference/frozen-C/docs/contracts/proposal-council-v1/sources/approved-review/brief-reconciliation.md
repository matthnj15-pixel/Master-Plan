## Required changes to the provisional contract

1. **Requested feasibility precedes negotiation.** First return and display the feasible requested edit with its exact geometry, quantities and forecasts. Then evaluate agree/counter/refuse against trusted authority and profile rules. Keep a refusal's feasible requested preview visible; a refusal offers no revision command. A counter has its own candidate, concessions and confirmation.
2. **The engine scores before character wording.** Model interpretation returns claims, evidence references and intent. Engine checks truth/currentness, priorities, quotas and existing caps, then applies one explicit pitch action. The optional reply describes that receipt and remaining concerns. Failed reply generation cannot reapply scoring or consume another pitch; a factual fallback keeps play moving. Invalid first-stage interpretation preserves input without consuming a pitch.
3. **False claims and unconfirmed promises are explicit negatives.** A feature absent from the current public plan cannot earn credit as an existing benefit. A separate true claim may still earn its own credit. Future conditions only become binding through a recognized confirmed game action; dialogue cannot create a route, sale condition, grant or favor.
4. **Partial scope requires acknowledgment.** Unsupported parts and material fitting changes remain visible. A useful supported subset can be offered, but accepting its reduced scope is distinct from the later post/apply action. It is never silently substituted for the original idea.
5. **Recovery is a separate private workspace.** The proposed bounded local store keeps drafts distinct from public saves and agenda entries. Restored intent/plots can be edited; cached forecasts, authorizations and receipts cannot be reused as commit authority. Changes to town, turn, proposal or site require a new engine preview. Explicit deletion differs from merely closing a sheet.
6. **Domain cases are in the first fixture package.** They use finite trusted authored facts/options and deterministic stance rules. Their operational concerns are not mislabeled as freight, alcohol-risk or farm-income simulation. Routine campaign play does not gain arbitrary route or ownership edits from fixture metadata.
7. **History and voice are scoped.** Supply confirmed relevant event IDs and relationship values, not an invented promise history or a full archive. Facts, scenario-authored rules, beliefs and flavor remain separate. The same candidate, profile and state produce the same material stance, authorization and engine effects even when prose varies.
